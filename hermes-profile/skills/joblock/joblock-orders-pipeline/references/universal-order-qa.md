# Универсальный контракт качества заказа

Корневой скилл `joblock-order-playbook` (источник — `portal/root_playbook.py`)
ставится в КАЖДЫЙ профиль через `clean_profile.sanitize()`, включая `empty`.
Это не инструкция под нишу, а предохранители, общие для всех заказов.

## Пять проверок до старта

1. **Вход полный.** Все материалы, доступы и ссылки на месте. Нет → спросить
   заказчика; не выдумывать доступы, сроки и результат.
2. **Инвентаризация активов.** `ls` рабочей папки и `sources/` ДО поиска.
   Поиск без неё тратит минуты на 403/404, хотя пригодные файлы уже на диске.
3. **Замок скиллов.** Во время заказа не редактировать и не перезагружать свои
   скиллы (`status: unchanged, dedup: true`, перечитывание references) — это
   дрейф профиля, а не выполнение. Скиллы меняются между заказами.
4. **Модель.** Проверить `model.default` в `config.yaml` именно этого профиля:
   оркестратор создаёт `ord-*` со старым конфигом шаблона.
5. **Формат сдачи.** Файл, абсолютный путь, размер/объём. Без этого «готово»
   не имеет смысла.

## Пейплайн

```
ТЗ → план (qa/plan.md) → работа → промежуточный QA (qa/checks.json) →
оценка (qa/score.json) → финальный QA → контракт (qa/deliver.json) → сдача
```

Промежуточная проверка — инструментом, с результатом в machine-readable виде:

```json
{"step":"render","tool":"short_video_media.py validate","ok":true,
 "details":{"width":1080,"height":1920,"duration":55}}
```

`ok: false` → чинить, не сдавать. Для PDF — сигнатура `%PDF-`, `pdfinfo`,
число страниц; для текста — длина/язык/отсутствие чужого ТЗ; для таблиц —
прочитать `openpyxl`/`pandas`, ячейки не пустые.

Три оси оценки (0–100): соответствие ТЗ, техническое качество, готовность
к сдаче. Порог 80 на каждой; ниже — возврат к шагу, её давшему. Число обязано
опираться на `qa/checks.json`, а не на самооценку в тексте.

Финальный контракт:

```json
{"artifact": ".../deliverables/master.mp4", "artifact_type": "video",
 "checks_passed": true, "score": {"match":92,"technical":95,"ready":90},
 "sources_count": 6, "credits_ok": true, "caveats": []}
```

Пока `deliver.json` нет — заказ не считается готовым, даже если агент написал
«готово» в чате.

## Таблица известных проблем

| Симптом | Причина | Профилактика |
|---|---|---|
| минуты на поиск файлов | поиск до инвентаризации | проверка 2 |
| агент правит скиллы вместо заказа | дрейф в середине | проверка 3 |
| качество «на словах» | нет machine-readable QA | checks/deliver |
| чужая история в топике | нет изоляции профиля | профиль + маршрут, не сессия |
| старая модель в заказе | оркестратор не наследует | проверка 4 |
| 403/404 при скачивании | обёртка вместо storage URL | скилл биржи |
| файл не дошёл в ТГ | метка до фактической отправки | send → mark |

## Установка и проверка

`root_playbook.install(profile_dir)` пишет `skills/joblock-order-playbook/SKILL.md`;
вызывать из `clean_profile.sanitize()`. Проверять точное множество скиллов
(тест изоляции) и фронтматтер: `description` ≤ 60 символов — длинный
description не даёт агенту корректный триггер загрузки.

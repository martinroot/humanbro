# Изоляция профилей и пользовательский поток JobLock

Справочник по machinery, собранной в портале и шлюзе. Только когда задача
касается профилей заказов, мультиплекса, ТГ-меню или запуска пейплайна.

## Граница изоляции — профиль, не сессия и не агент

- Агент (субагент) живёт внутри профиля и делит его скиллы, модель, доступы.
  Сессия — только ветка истории в `state.db`, скиллы не изолирует.
  Границей выбора сделан **профиль**: скиллы + модель + история + доступы.
- В мультиплексе (`gateway.multiplex_profiles: true`) активный профиль для
  чата — это профиль маршрута `default-chat`, а не имя запущенного процесса:
  шлюз крутится под служебным `slug` и обслуживает все профили. Читать
  `active_profile()` из `profile_routes`, а не из `ps`过程的 running-списка.
- `switch()` в мультиплексе меняет `profile` у маршрута `default-chat` в
  `profiles/slug/config.yaml` и перезапускает только шлюз `slug`; рабочий
  `default` не трогать. Ждать реального `running` (~40 с) перед возвратом.
- Ключ сессии становится `agent:<profile>:...:thread_id` только когда профиль
  попадает в `build_session_key`; при `multiplex_profiles: false` ключ всегда
  `agent:main:...` — изоляции нет, сколько профилей ни создай.

## Чистка и провизия профилей

- Мультиплексный шлюз держит `state.db` ВСЕХ профилей открытыми. Перед
  удалением мусорных профилей сначала `hermes -p slug gateway stop`, иначе
  `rm -rf` падает с `Device or resource busy`, затем стартовать обратно.
- Отключать `Hermes_Gateway_Watchdog` и per-order `Hermes_Gateway_ord-*`:
  watchdog поднимал старый `slug` и перезаписывал состояние.
- Новый профиль заказа: `--clone-from <шаблон>` + обязательно
  `clean_profile.sanitize()` — вычищает `memories/`, `sessions/`, вкладывает
  ТЗ заказа. БезMemory/USER шаблона агент читает чужую историю.
- `clean_profile.sanitize()` также ставит корневой скилл
  `joblock-order-playbook` (универсальный пейплайн + QA-гейты + оценки) —
  даже в пустой профиль. Не удалять его при чистке скиллов.

## Базовый каталог

Ровно три рабочих профиля: `video-shorts`, `pdf-edit-pro`, `empty`.
Промежуточные `ord-*`, `flyer-*`, `design/dev/text/retouch` — мусор итераций,
удаляются по явной команде владельца. Каталог в базе (`profile_templates`)
должен совпадать с диском: сверять `/api/profiles` и `skills_count`.

## Пользовательский поток в ТГ (ФОРМАТ)

Владелец поправил: **не нумеровать пункты**, а дать последовательность
сверху вниз. Кнопки идут в порядке шагов, technical спрятан в конец.

```
📂 Заказы
🤖 Каталог агентов
▶️ Взять в работу   (карточка: ⚙️ Выполнение)
✅ Закрыть
🔧 Техника          (внутри: профили, шлюз, топики, активный профиль)
```

Карточка заказа:
```
📂 Заказы → 🤖 Каталог агентов → ▶️ Взять в работу → ⚙️ Выполнение
→ ✅ Закрыть заказ → 🔧 Техника заказа
```

Технические действия (создать профиль, собрать шаблон, передать шлюзу,
тема заказа, отправить результат) — только внутри «🔧 Техника».

## Опции запуска нового пейплайна из `empty`

При выборе пустого профиля показывать два варианта:

- **«С нуля»** (`fresh:`) — изолированный профиль + топик + MLL-оценка +
  файлы заказа (`_starter_files`, `_оценка_заказа`), корневой QA подключается
  через `clean_profile.sanitize()`.
- **«Собрать из скилов из базы»** (`frombase:`) — полный конвейер:
  1. `pipeline_composer._кандидаты_из_базы(order)` — подбор из `skill_library`
     с синонимами ru→en и дедупом;
  2. `pipeline_composer.compose()` — MLL подгоняет скиллы под ТЗ, строит шаги,
     проверки и три оценки 0–100; fallback детерминированный при отказе MLL;
  3. `build_profile()` — гейт: любая ось < 80 блокирует сборку;
  4. на выходе профиль со скиллом `pipeline` + MLL-оценка + файлы + топик.

Не запускать агентов ради проверки новых опций — только конфигурация и
холостые прогоны сборки в temp-каталоге.

## Перенос наработок из профиля заказа в шаблон

После успешного заказа сравнить `diff -rq <ord-*>/skills <template>/skills`:
новые скиллы и обновлённые `SKILL.md` перенести в шаблон, бэкап перед копированием.
Так из заказа WZ-22548213 в `video-shorts` приехали `free-stock-footage-sourcing`,
`russian-voiceover-karaoke`, `style-variations.md`. Синхронизировать
`profile_store.put_skill()` и счётчики в `/api/profiles`, поправить ожидаemia
в тестах изоляции/меню. Не удалять старые скиллы при добавлении новых —
пересобирай весь набор из wanted-списка. Удаление «всех, кроме двух новых»
через цикл `delete_skill` оставляет профиль с двумя скиллами вместо восьми:
удалять по СПИСКУ на добавление, а не «всё, кроме».

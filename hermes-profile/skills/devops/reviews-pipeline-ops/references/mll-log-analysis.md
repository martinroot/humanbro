# MLL-панель на /portal/log: контракт и устройство

Кнопки страницы лога: `⬇ Скачать лог (300)`, селект моделей MLL (цены в строке), `🔍 MLL — анализ лога`, `MLL → TASK`. Всё живёт в FastAPI-слое портала (`C:/sites/joblock/portal/app.py`), страница — `live_log.py`.

## Роуты
- `GET /api/log/settings` → `{модель, модели[10], key_задан, цены}` — цены тянутся из `GET https://openrouter.ai/api/v1/models` (`pricing.prompt/completion` за токен × 1e6 → $ за 1M), кэш в `mll_settings.json` (обновление в сутки или по `принудительно`).
- `POST /api/log/settings` `{модель?, key?}` — сохранить выбор; модель из фиксированного списка (только своя, не провайдерская витрина).
- `GET /api/log/download` — лента 300 строк + шапка (фаза/ожидания/инструмент) как attachment.
- `POST /api/log/analyze` `{модель?}` — промт из `live_log.собрать()`: текущее время (UTC+3) ОБЯЗАТЕЛЬНО (для оценки простоя), глобальное состояние (фаза, ожидания, очередь, шаги), 300 записей лога; строгий JSON-контракт: `task: false` = процесс непрерывен, иначе `task` = ровно ОДНА задача агенту (≤250 знаков, с глагола) + `блокер` + `рекомендации[]`.
- `POST /api/log/task` `{текст}` — канал 1: трекер `http://5.144.179.170:8080/api/task_queue.php` **БЕЗ ключа**: трекер доверяет IP серверов агентов из карточек проектов (WINTASK = 195.63.128.99) — голый POST с телом `{project_ref, title, prio, source, note}` → `{ok, task_id, dup}`. Ключ — только запасной путь для чужого адреса (заголовок `X-Ingest-Key` с обрезкой пробелов / `Authorization: Bearer` / поле `ingest_key` в теле). Лимиты трекера: `dup:true` на незакрытый дубль; не больше 3 открытых задач от одного `source` в направлении (далее 429 — это гейт, не сбой); id в дереве единицы (~105) — сотни в ответе значит, ушла не туда. Канал 2 (fallback): `POST /api/tasks` портала, статус карточки только `todo` (ENUM: todo/doing/done/blocked/failed).
- **Тест канала:** `POST /api/log/task` с `{"текст": "…"}` → ответ `{ok, канал, task_id, dup}` подтверждает связь в обе стороны (задача приходит сообщением в WINTASK). Тело посылать ТОЛЬКО из UTF-8 файла (`--data-binary @file.json`): git-bash curl шлёт кириллицу в `-d` как CP1251, роут падает на `req.json()` с `UnicodeDecodeError … byte 0x97` и отвечает `{ok:false, "internal error — см. portal_errors.log"}` — выглядит как поломка канала, а сломан клиент. **Тестовую задачу после проверки закрыть `TASK|<id>|DONE` в WINTASK** — открытые задачи одного `source` в трекере ограничены (лимит 3, дальше 429), и оставленный тест съедает слот настоящей задачи.

## Обязательные правила надёжности
1. **Весь блок «сбор промта + вызов модели» — в `run_in_executor`**, иначе блокирующий urllib ложит event loop: во время анализа молчит поллинг страницы. Внутренний POST к самому себе (`/api/tasks`) из async-роута — то же самое (дедлок: loop не обслуживает свой же входящий запрос) → тоже executor.
2. **`max_tokens` с запасом на reasoning**: reasoning-модели (glm-5.3 и подобные) пишут thinking в поле `reasoning` ДО контента; при тесном лимите получается `finish_reason: length` + `content: null` → роут падал на `.strip()` None в 500, UI показывал криптичный `Unexpected token 'I'`. Лимит 6000 — контент успевает; пустой content ретраить 3 раза (провайдер флапает на повторах), затем 502 с понятным текстом «модель вернула пустой ответ».
3. **Сырой ответ провайдера при пустом content — писать в журнал** (finish_reason + payload): без этого причина «длины/фильтра» нечитаема.
4. **middleware-журнал `portal_errors.log`** рядом с app.py: `launch_portal.bat` не перенаправляет stderr, любая необработанная ошибка иначе исчезает; сам middleware регистрировать ПОСЛЕ `app = FastAPI(...)` (иначе NameError при импорте и портал не стартует).
5. **Цена каждого прогона — на виду**: в ответе `analyze` блок `usage: {in, out, usd, in_usd_за_1m, out_usd_за_1m}` (cost берём у провайдера, иначе считаем по прайсу модели), в шапке результата — `IN N ток · OUT M ток · $X (in $A / out $B за 1M)`. Владелец: «Выводи цену за in/out у моделей и при ответе показывай сколько IN/OUT и цену».
6. Стандартный блок «портал-роута с сетью» (это же правило главного SKILL.md): любая тяжёлая работа — в отдельном потоке, ошибки — в JSON, не в HTML-500.
7. **Промт и автотикер видят ТОЛЬКО то, что попало в ленту и её журналы** (правило владельца: «нужно чтобы эти все проблемы выходили в логе, иначе MLL не сможет пофиксить»): сбой шага, падение подъёма профиля, прокси-ошибка, stderr фонового скрипта обязаны заканчиваться строкой в источниках ленты (выводы шагов, `runner.log`, `portal_errors.log`), а не жить только в stdout одноразового скрипта — иначе анализатор ставит задачу вслепую.

## Авто-MML: галочка и тикер 15 минут
- Галочка `⏱ авто-анализ каждые 15 мин` в mllbar; состояние — поле `авто` в `mll_settings.json` (POST settings `{авто: bool}`). Цикл — startup-задача FastAPI (`on_event("startup")` → цикл `asyncio.sleep(900)`), тик читает настройку каждый раз — вкл/выкл действует без перезапуска портала.
- Тик (`_авто_шаг`): при включённой галочке — анализ по той же механике, что роут (промт из ленты, ретрай пустого content, usage/цена), затем `task`-строка → постановка в трекер (IP-trust), `task: false` → ничего не ставим. Итог тика (время, статус, task_id/канал, блокер, usage, модель) пишется в `авто_последний` того же файла.
- Статус на странице: `GET /api/log/live` обогащается полем `авто {вкл, последний}` → шапка показывает `авто: вкл · последний HH:MM → задача поставлена (трекер id N)`. Формулировка владельца: «Сделай галочку, если стоит — Агент каждые 15 минут анализирует и отправляет ЗАДАЧИ по логу на исправление».
- Тест одного тика без ожидания 15 минут: `asyncio.run(app._авто_шаг())` — только в ЧИСТОМ subprocess (отдельный python, в путях нет каталога reviews): `reviews/queue` перекрывает stdlib `queue`, и `run_in_executor` падает на `queue.SimpleQueue`; в портале этих путей нет, ошибка именно тестового окружения.

Дефолт — первый из списка владельца; для дешёвых регулярных прогонов подходит модель с минимальными out-тарифами (основная статья расхода — ВЫХОД: reasoning-модели генерируют 5–6K токенов на прогон, нерассуждающие — сотни).

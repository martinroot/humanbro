# Сдача заказа с песочницы

Протокол работы профиля с заказом: от карточки в очереди до файла, который
заказчик может скачать. Песочница — localhost:8789, она повторяет живую биржу,
включая её неприятности.

## Жёсткие правила

1. **Нет материала — не начинать работу.** Файл не приложен? Задай вопрос
   клиенту через `/api/answer` и жди. Это правило сильнее любого срока.
2. **Сдача подтверждается фактом, а не нажатием.** После отправки формы
   перечитай страницу заказа: файл обязан быть в списке сданных. Нет файла —
   сдачи не было, даже если форма вернула 303.
3. **Закрытое задание — «опоздали», а не ошибка.** Заказ могли забрать, пока мы
   работали. Это не повод чинить селекторы.
4. **Токены не печатать** — ни в отчёт, ни в лог. Читать из
   `C:\sites\joblock\portal\.env` по необходимости.

## Маршруты

```
GET  /                                лента
GET  /order/<id>                      заказ: ТЗ, материалы, чат, форма сдачи
POST /order/<id>/respond              отклик (только на open!)
POST /order/<id>/chat                 сообщение в чат
POST /order/<id>/reply                сдача файлом (multipart, поле files)
GET  /material/<id>/<файл>            скачать материал
POST /api/answer                      клиент ответил и прислал файлы
POST /api/accept                      клиент принял результат (order=<id>)
GET  /api/state                       состояние: заказы, чат, события
```

## Порядок шагов

1. Взять заказ из очереди: `GET /api/win/bids` на портале :8701
   (заголовок `x-fabra-parser-token`).
2. Открыть `/order/<id>`, прочитать ТЗ — это панель сразу за заголовком
   «Техническое задание», **не первый** `.panel` (там может быть бейдж
   «Вы откликнулись»).
3. Скачать все материалы через `/material/<id>/<файл>`.
4. Нет файлов → вопрос клиенту (`чего_не_хватает()` из otklik.ts) и стоп.
5. Сделать результат. Формат и размер — из ТЗ, дословно.
6. Сдать файлом через `/order/<id>/reply`.
7. **Перечитать заказ** и убедиться, что файл в блоке «Сдано исполнителем».
8. Доложить: `POST /api/win/bid-sent` на :8701 — только по факту отправки.

## Ловушки, на которых уже падали

- **Название заказа** — `contenteditable` (Trumbowyg), а не textarea. Заполнять
  `.trumbowyg-editor`, потом проверять, что значение доехало.
- **Срок выполнения** — выпадающий список на `position: fixed` без тега
  `select`. Проверять видимость через `getClientRects()`: у `position: fixed`
  `offsetParent` всегда null, и фильтр выкидывает все варианты.
- **Кириллица в `page.evaluate`** ломает сериализацию функции — `ReferenceError`
  прямо в браузере. Внутри evaluate только латиница.
- **`page.evaluate` берёт ровно один аргумент**; два — `Too many arguments`.
  Упаковывать в объект.
- **Список откликов исчерпаем**: `bid-sent` навсегда убирает задание из очереди
  (`UNIQUE` по source+external_id). Смоук обязан возвращать карточки.

## Проверка качества результата

Перед сдачей:
- размеры ровно как в ТЗ (например 1200x1200 — не «примерно»);
- формат: PNG для фото, SVG для логотипов;
- файл открывается и не пустой (проверить размер в байтах и сигнатуру);
- если ТЗ требует несколько размеров — все размеры в одном ответе.

## Обратная связь

Приёмка идёт через kanban: `request-review` → проверяющий → `complete` или
`request-changes`. Причина в `request-changes` обязательна и конкретна: что
не сошлось с ТЗ, а не «не понравилось».

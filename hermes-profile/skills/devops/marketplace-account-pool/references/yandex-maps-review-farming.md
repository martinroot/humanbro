# Фарм перед отзывом: что, где, зачем

Расширенный фарм нужен, потому что заказчик проверяет не только текст
отзыва, но и ПРОФИЛЬ аккаунта. Реализация — `yandex-farm.ts`:

```
bun yandex-farm.ts <cdpPort> <urlКарточки> <город> [паузаСек] [папкаСкриншотов]
```

## Порядок действий и зачем каждое

| # | Действие | Зачем |
|---|---|---|
| 1 | `clearPermissions()` + `Emulation.setGeolocationOverride` | Заказчик просит «ОБЯЗАТЕЛЬНО отключить гео» и смену географического расположения. Разрешение браузера закрываем, координаты подменяем на точку в городе задания со случайным сдвигом — Яндекс видит «другой район», профиль выглядит живым |
| 2 | Открыть карточку, прочитать, **скриншот** | Доказательство, что карточка открыта; скриншот — материал для заказчика, если попросит |
| 3 | Нажать «Показать телефон» (не звонить) | Заказчик пишет «нажмите на номер (не звоните!)». Кнопка — не `<button>`, ищется по тексту среди span/div |
| 4 | Пройти ВСЕ вкладки: Обзор, Товары и услуги, Фото, Отзывы, Филиалы, Особенности, Похожие места — с прокруткой | «похододите по всем вкладкам… просто тыкайте во все вкладки» |
| 5 | Прокрутить фото, открыть 3 снимка | Фото смотрят, а не просто открывают вкладку |
| 6 | **Прочитать чужие отзывы**: раскрыть «Читать полностью», прокрутить список с задержкой, **скриншот страницы отзывов** | «читать другие отзывы и т.п.» — читатель должен реально открыть тексты, иначе в профиле нет следов |
| 7 | Лайкнуть 2–3 положительных отзыва | «лайкните пару отзывов». Лайк — клик по счётчику `.business-reactions-view__container`, кнопки «Полезно» в Яндексе нет |
| 8 | **Маршрут до заведения** — два раза, с разных стартов (центр города и вокзал), скриншоты | «без маршрута отзыв не проходит». Старт — любой пункт В ГОРОДЕ ЗАДАНИЯ, а не из другого города |
| 9 | Пауза «живой» сессии (3–10 с) | Паузы между действиями — профиль не должен выглядеть автоматом |

## Что важно

- **Город для маршрута — из адреса карточки**, не из текста задания. Ошибка
  была: «Территория АКПП» оказалась в Орле, маршрут строили из Белгорода
  (320 км вместо 8,7).
- **Регион задаётся в настройках самого Яндекс-аккаунта и в геолокации
  браузера — НЕ подменой прокси.** Владелец прямо запретил менять прокси
  ради «города»: резидентный IP, который внезапно меняет город, — куда
  более сильный сигнал, чем снимаемая нестыковка. Гео — через
  `Emulation.setGeolocationOverride` плюс регион в настройках аккаунта.
- **Город из ТЗ должен быть в таблице координат.** Нет города — подмена
  молча уходит в город по умолчанию, и весь фарм (маршрут, «выход из
  центра») делается из чужого города. Отсутствие города в таблице — это
  не «город по умолчанию», это баг, который виден только по адресу маршрута.
- **Координаты САМОЙ карточки (`ll=` из её URL) приоритетнее таблицы
  городов.** Точка в центре города может быть в 20 км от объекта, а ТЗ
  требует маршрут «с расстоянием до 15 км» — такой фарм проваливает
  требование, хотя отчёт показывает «маршрут построен». `ll=` из ссылки —
  это и есть точка заведения, и она не может быть чужой. Порядок: (0) если
  в URL есть `ll=` — берём его; (1) иначе город ищется в таблице ТОЧНЫМ
  совпадением, и только потом — по префиксу (иначе соседние города
  меняются местами: «саратов» начинается с «сама», и фарм уезжает в
  чужой город, что не видно нигде — координаты подставляются, маршрут
  строится, отзыв выходит, но не оттуда); (2) если города нет в таблице —
  координаты карточки всё равно лучше города по умолчанию; (3) город по
  умолчанию допустим только последним и обязан попасть в отчёт как «город
  не определён», а не как «Москва».
- **Скриншоты сохраняются** в `reviews/data/shots/` — это и доказательство
  работы, и материал для отчётности.
- **Фарм повторяют за 2 часа до отзыва** («за два часа до отзыва повторите
  эти же действия еще раз»).
- **Пауза между отзывами** — разные аккаунты и разное время, иначе «примут
  за спам».

- **POI из короткой ссылки — отдельная форма карточки, и детектор
  «дождалась карточки» на ней не срабатывает.** У поискового POI заголовок
  лежит в `h1`, а не в `orgpage-header`, а вкладка «Отзывы N» — это span
  без ссылки, поэтому селекторы её не видят. Детектор готовности должен
  принимать и `h1`, и вкладку «Отзывы» по ТЕКСТУ страницы, иначе фарм
  падает «не догрузилась за 45 с» на живой карточке.
- **Короткая ссылка `/-/CX…` раскрывается один раз, и дальше работаем с
  раскрытым URL.** Он несёт `poi[point]`/`poi[uri]` и `ll` — координаты
  объекта. Раскрытый URL годится и фарму, и снятию скрина; строить путь к
  организации по названию нужно только когда отзывы на POI писать нельзя.

## Правила биржи, которые нельзя нарушать

- Негативных и неправдивых отзывов, отзывов конкурентам, рефералок — нет.
  Только честный положительный отзыв о клиентском бизнесе.
- Один аккаунт — одна карточка. Несколько отзывов — разные аккаунты.
- Покупка/аренда аккаунтов правилами Workzilla прямо запрещена: риск бана
  без предупреждения.

## Как заказчики наказывают за «нефарм»

Проверяется стандартными способами: выход из аккаунта, инкогнито, другое
устройство. То есть заказчик смотрит профиль извне: не было вкладок, не
было маршрута, нет лайков — отзыв не проходит. Отзыв может быть уже
опубликован, но заказчик его не примет и не заплатит.
